## Added
- `store::changesets::is_issued_handle`: the shape of a handle the server issues (`gen_random_uuid()::text`: 36 characters of lowercase hex in the 8-4-4-4-12 grouping).
- `http::api::malformed_name_tests`: one test that sends every `/api/v1` route (and the legacy `/catalogs/{name}/export` and `/import`) that takes a user, team, catalog, key, grant, sign-in code, changeset, setting, mail or `/me` id from its path a NUL, a capital, `..` and a 5000-character name, and asserts the route's usual 404 (the one 400 is an unlock's numeric id, which axum refuses). It also sends a NUL in the body fields and query filters that name a user, team, catalog or key, and asserts none answers 5xx. A unit test covers `is_issued_handle`, and `by_handle` has a NUL case.

## Changed
- `DELETE /changesets/{handle}`, `GET /changesets/{handle}/diff`, `POST /changesets/{handle}/publish` (and the MCP `discard`, `pending_changes` and `publish` tools) answered 500 for a handle holding a NUL, because Postgres refuses a NUL in text. `changesets::by_handle` now answers `None` (the existing unknown-changeset 404) for a handle that is not of the issued shape, before SQL.
- `GET /catalogs/{catalog}/maintenance/runs/{run}` and `.../findings/{finding}` (and the MCP maintenance tools that take a finding id, run id, work id or lease token) answered 500 for an id holding a NUL. `maintenance::runs::no_nul` (used by `required_id`, `renew`, `close` and `submit`) answers the existing not-found for it. Only a NUL is ruled out, since fixtures and older rows use ids that are not generated hex.
- `POST /keys` and `POST /oauth/codes` answered 500 for a NUL in `catalogs`. `keys::catalog_ids` now answers `CatalogNotSelected` (the existing 404) for a name `catalogs::is_valid_name` refuses, before SQL.
