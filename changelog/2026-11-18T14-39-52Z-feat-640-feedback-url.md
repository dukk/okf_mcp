# Feat #640: a `feedback_url` setting shows a "Send feedback" link in the console

Issue #640.

## Added
- `feedback_url` branding setting (`SettingKey::FeedbackUrl`, appended to
  `SettingKey::ALL`): an `https://` URL with a host, at most 500
  characters, no whitespace or control characters; `none` clears it. An
  email address is refused. Default is unset.
- `Brand::feedback_url`, so `GET /ui/brand.json` returns
  `{"product_name", "support_contact", "feedback_url"}` (`null` when
  unset); `brand_in` loads the new key.
- Console: a "Send feedback" link (`target="_blank" rel="noopener"`) in
  the sidebar footer, hidden until `feedback_url` is set. `shell.js`
  sets its `href` from the brand JSON (a property, never built HTML), and
  the Settings page lists and edits the setting like the others.
- Tests: settings unit tests (validation, `brand()` and `brand_in`,
  `none`, the audit entry), the `/ui/brand.json` test, and a UI journey.

## Changed
- The URL half of `check_support_contact` is now a shared helper,
  `is_https_url`, which `check_feedback_url` also uses.
- `docs/operations.md`: the Settings table and the `/ui/brand.json` row.

## Notes
- The audit entry records the URL (`audited_value` returns it): a URL is
  not personal data, unlike `support_contact`, which may be an email
  address.
- With `feedback_url` unset the console is unchanged: the link stays
  hidden.
