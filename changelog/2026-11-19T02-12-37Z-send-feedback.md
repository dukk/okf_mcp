# send_feedback forwards user and agent feedback to the operator's Forminit form

## Added
- The `send_feedback` MCP tool (`src/mcp/feedback.rs`, issue #674): `message`, `kind` (`bug`, `confusing`, `missing`, `praise`, `other`; default `other`), `from` (`user` or `agent`; default `agent`), `tool`, `rating` (1-5). It needs no catalog and works for any credential, `read` included, over an API key or an OAuth grant. It returns `{sent: true, id}` at once. Annotations: not read-only, not destructive, not idempotent, open-world (a new `EXTERNAL` class in `src/mcp/annotations.rs`, and a fifth "external" kind in `docs/reference/tools.md`).
- The `[feedback]` config table: `forminit_form_id` (1 to 64 of `A-Za-z0-9_-`, so it can never change the URL's host or path), `api_key_env` (optional), `worker` (default `true`), `max_per_hour` (default 10, 1 to 1000), `retention` (default `"30d"`, 1 day to 10 years). It refuses unknown keys. Without the table the tool is not registered on the session's router, so it is neither listed nor callable, and nothing is sent.
- Migration `0022_feedback.sql`: the `feedback` table (the forwarded fields, the calling key's id for the rate limit, status `pending`/`sent`/`failed`, attempts, last error, Forminit's `submission.hashId`, created and finished times).
- Delivery in `src/mail/feedback.rs`, on the mail queue's apalis-postgres machinery in a queue of its own (`send_feedback`): the tool inserts the row and the job (payload: the id only) in one transaction; a worker posts `{"blocks": [...]}` to `https://forminit.com/f/<form id>` with `X-API-KEY` when a key is configured, retries 429, 5xx and network errors with the mail backoff for 10 tries, and fails any other 4xx at once with Forminit's error code. The hourly prune deletes `sent` rows after `retention`. Delivery is at-least-once: fetching is exclusive in normal operation, but a retry after an unconfirmed or unrecorded acceptance (a timeout after Forminit took the post, or a failed `sent` update) can post a duplicate. Each submission carries a `feedback_id` text block (the row's random id, as the tool returns it) so the operator can de-duplicate in Forminit.
- One line in the server instructions (`FEEDBACK_INSTRUCTIONS`), sent only when `[feedback]` is set.
- `McpProbe::request` in the tool test support, for `tools/list`.

## Changed
- `src/mail/queue.rs`: `reschedule_job`, `worker_pool_named` and `process_worker_name` are the shared forms of the mail worker's helpers, so the feedback worker reuses them.
- `OkfServer` carries its instructions per session, and drops `send_feedback` from its router without `[feedback]`.
- `tool_label` (the metrics' tool allow-list) includes the external tools.
- `docs/operations.md`: the `[feedback]` keys, their checks, a Feedback section (what is sent, limits, delivery, retention, reading failed rows), and the worker in the multi-replica notes.
- `docs/reference/tools.md` regenerated; its intro now has a blank line before the tool table, which rendered as part of the list.

## Notes
- The API key is read at start-up from the variable `api_key_env` names (as the mail secrets are), held in a `SecretString`, and sent as a sensitive header value. `Forminit`'s `Debug` prints `<set>`, never the key. An unset or blank variable stops `serve`, naming the variable only.
- The rate limit counts the credential's rows of the last hour under a per-credential transaction-level advisory lock, so it holds across replicas and concurrent calls; no Redis limiter is involved, and none was needed.
- Only Forminit's error code (an upper-case token) or `HTTP_<status>` is stored and logged from a refusal, never its free text.
- The outbound client follows the CIMD and OIDC clients' conventions: no redirects, a timeout (30 s), the `okf-mcp/<version>` user agent, HTTPS only. The origin can be overridden only by a `#[cfg(test)]` field that TOML cannot set.
- The `rating` block shape (`{"type": "rating", "name": "rating", "value": N}`) follows the issue; Forminit's public documentation found while implementing confirms the `text` and `sender` shapes but not a `rating` block type.
