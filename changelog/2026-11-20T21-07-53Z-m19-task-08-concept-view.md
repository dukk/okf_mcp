# M19 Task 08: the concept and document views

## Added
- `src/http/read/js/screens/concept.js`: breadcrumbs, title, outline, body
  and "Linked from". A section route (`?s=<slug>`) reads `?full=true` first,
  so the heading to scroll to is never missing. The concept and its links
  are read together, each wrapped in `ctx.settle`, and the refusals of both
  are drawn once, by `ctx.drawWorst`. A concept the server shortened shows a
  "Show the whole concept" button; its refusals go through `ctx.fail` (a 401
  or a lost grant acts as on any read), and only an offline failure shows a
  notice. Backlinks use `hrefFor`, so a `log.md` or `AGENTS.md` opens as a
  document and an `index.md` as its folder.
- `src/http/read/js/screens/document.js`: a `log.md` or `AGENTS.md`, read
  through `/documents`; its refusals are handled by `main.js`.
- Journeys in `tests/ui_e2e/read.rs`, with a `server_with_outline_limit`
  helper and an empty-concept fixture: `a_concept_shows_its_body_follows_links_and_lists_backlinks`
  (the body link is rewritten to `#/v/main/systems/beta.md?s=settings`, and
  the screen shows no stray "null"), `a_log_opens_as_a_document`, and five
  for "Show the whole concept": `the_whole_concept_replaces_the_outline_notice`,
  `an_empty_concept_has_no_show_whole_button`,
  `the_whole_concept_is_not_available_offline_and_can_be_retried`,
  `show_the_whole_concept_after_losing_the_grant_evicts_the_catalog` and
  `a_late_whole_concept_does_not_touch_a_newer_screen`.

## Changed
- Production code: only `concept.js` and `document.js`, which replace the
  placeholder screens. Nothing else under `src/` changes.
- `tests/ui_e2e/read.rs`: the journeys above, and `server()` now calls
  `server_with_outline_limit`.
- The plan (`docs/superpowers/plans/2026-11-20-mobile-reader-pwa.md`), with
  dated notes: Task 8 records the shipped behaviour (a shortened concept is
  `body_html == null`; the whole-concept handler returns once its screen is
  gone), lists the new journeys, and drops `route.js` from its commit line
  (this task does not change it); Task 11 is told not to add
  `show_the_whole_concept_after_losing_the_grant_evicts_the_catalog` again,
  as it landed here.

## Notes
- Apart from the above, the plan's Task 8 code matched the shipped `api.js`,
  `route.js`, `parts.js` and the `ctx` that `main.js` builds.
- The claims audit found that drawing the title, outline and body with the
  native `view.append` printed the text "null" for a concept with no
  sub-headings (the outline is null; issue #302 in `dom.js`). The concept
  screen now draws them with `fill`, and the concept journey checks for it
  (it fails without the fix). `me.js` has the same pattern for a session
  with no email; it is not part of this task.
- Review of PR #842: a shortened concept is `body_html == null` (an empty
  concept's `""` draws an empty body with no button), and the "Show the
  whole concept" handler returns before the banner or any DOM change once
  its screen is no longer shown (a refusal still goes through `ctx.fail`).
  Each fix's journey fails without it. The lost-grant journey asserts
  `#/c?gone=main` and the eviction, not `#catalog-gone`, because the picker
  is still a placeholder until #814.
