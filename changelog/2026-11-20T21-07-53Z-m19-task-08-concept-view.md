# M19 Task 08: the concept and document views

## Added
- `src/http/read/js/screens/concept.js`: breadcrumbs, title, outline, body
  and "Linked from". A section route (`?s=<slug>`) reads `?full=true` first,
  so the heading to scroll to is never missing. The concept and its links
  are read together, each wrapped in `ctx.settle`, and the refusals of both
  are drawn once, by `ctx.drawWorst`. A concept the server shortened shows a
  "Show the whole concept" button; its refusals go through `ctx.fail` (a 401
  or a lost grant acts as on any read), and only an offline failure shows a
  notice. Backlinks use `hrefFor`, so a `log.md` or `AGENTS.md` opens as a
  document and an `index.md` as its folder.
- `src/http/read/js/screens/document.js`: a `log.md` or `AGENTS.md`, read
  through `/documents`; its refusals are handled by `main.js`.
- Journeys `a_concept_shows_its_body_follows_links_and_lists_backlinks`
  (the body link is rewritten to `#/v/main/systems/beta.md?s=settings`) and
  `a_log_opens_as_a_document` in `tests/ui_e2e/read.rs`.

## Changed
- Nothing outside the two placeholder screens.

## Notes
- The plan's Task 8 code matched the shipped `api.js`, `route.js`,
  `parts.js` and the `ctx` that `main.js` builds, so it was used as written
  and the plan needed no correction. The plan's commit step lists
  `route.js`, which this task does not change.
- The claims audit found that drawing the title, outline and body with the
  native `view.append` printed the text "null" for a concept with no
  sub-headings (the outline is null; issue #302 in `dom.js`). The concept
  screen now draws them with `fill`, and the concept journey checks the
  screen has no stray "null" (it fails without the fix). `me.js` has the
  same pattern for a session with no email; it is not part of this task.
- Review of PR #842: a shortened concept is `body_html == null` (an empty
  concept's `""` draws an empty body with no button); the "Show the whole
  concept" handler returns before the banner or any DOM change once its
  screen is no longer shown (a refusal still goes through `ctx.fail`). New
  journeys cover the button: the whole body replaces the notice, an empty
  concept has no button, an uncached offline read shows a notice and keeps
  the button usable, a lost grant evicts the catalog and goes to the picker
  (moved here from Task 11, see the plan), and a late answer leaves a newer
  screen and the banner alone. Each fix's journey fails without it.
