## Review round 1 (PR #667)

- `CatalogMeta` carries the catalog's `name`, so creating a catalog drops a
  cached "no such catalog" entry (the new id maps to nothing yet).
- Invalidation epochs exist only while a load is in flight. An invalidation
  of an uncached key keeps no state, so the map no longer grows with the
  population. Minimum generations follow the same rule.
- Every in-place catalog refresh re-inserts the cache entry
  (`Bounded::reweigh`), because moka weighs only on insert, and a catalog
  that grows past the budget is evicted.
- A request pins the snapshot (`Arc<Loaded>`), not only the `CatalogState`,
  so two reads in one request see one generation even across an in-place
  refresh.
