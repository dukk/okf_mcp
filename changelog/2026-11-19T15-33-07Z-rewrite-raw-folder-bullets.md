## Added
- `raw_names` in `src/okf/ops/replay.rs`: the destinations an unencoded listing of a target can have. For a folder's `index.md` it adds the folder link older versions wrote under `# Sections` (`name/` and `/folder/`) beside `name/index.md` and `/folder/index.md` (issue #731). Concept targets get the same names as before.
- Tests: an in-place rewrite of each raw folder form (space, `)`, `#`, `:`), as `name/` and `name/index.md`, relative and `/`-absolute, with a fragment and trailing text; a folder in the root index; a raw duplicate beside a working bullet (`name/`, `name/index.md` or `name`), in either order and twice; a `%XX` name and a link to another existing folder left alone; an absolute `:` link that already resolves; idempotence; replay onto newer text (rewrite, removal, a parsed link, a working bullet replay cannot read as the folder); and a staged repair published after a concurrent edit of the parent index.

## Changed
- `repair_indexes`, and the operator's `okf-mcp catalog repair-indexes`, now fix raw folder bullets in a parent's `# Sections` the way #717 fixed raw concept bullets. `* [My docs](my docs/) - x` becomes `* [My docs](my%20docs/) - x`, keeping the label, fragment and trailing text. When another bullet already links the folder, the raw one is removed. Before, the folder pass checked `lists_target` alone, so it appended a second, working bullet beside the broken one. The folder pass now runs `rewrite_raw_listings` on the parent index first, then checks `already_lists`. Each fix is a `RewriteRawListing` replay op with a note that names the folder as `/d/my docs/`.
- The `index` tool description now says that `repair_indexes` rewrites an older raw bullet. The `repair_indexes` description, `docs/reference/tools.md` (regenerated), `README.md`, `docs/operations.md` and the CLI help name folder listings too.

## Notes
- Rules 0-3 of `lists_raw_target` apply unchanged to a folder target. Rule 3 checks the parsed link against the real workspace, where a folder resolves to its `index.md`. So `[A](a)b/)` and `[A](a#b/)` are folder `d/a`'s working listing when `d/a` exists, and are left alone.
- Publish replay is as conservative as for concepts. It redoes a rewrite only while the raw line is still there, and only for the space and `:` forms. Its removal check cannot see directories, so a working bullet written without a trailing slash (`[A](a%20b)`) does not count there. The raw bullet is then rewritten, not removed, which leaves two working bullets for the folder (`repair_indexes` does not merge working duplicates). A listing is never dropped.
