# M15 Task 2: the metrics provider and the `/metrics` listener

Issue #463, Task 2 of `docs/superpowers/plans/2026-11-15-okf-mcp-m15-observability.md`.

## Added

- `src/telemetry/metrics.rs`: the typed `Metrics` handle (`okf.build.info`), `Outcome`, `SECONDS_BUCKETS`, `seconds_histogram`, `tool_label` (a tool name becomes a label only when it is registered, else `other`) and `observe_export_failures`, which puts `okf_telemetry_export_failures_total` (every signal and reason, zero until a failure) on every scrape.
- `src/telemetry/scrape.rs`: `serve`, a separate unauthenticated listener answering `GET /metrics` in the Prometheus text format. The body is encoded into a buffer first, so an encoder error is a 500 with no body, never a partial exposition. Every other path is a 404.
- `[telemetry.prometheus] listen`, refused when it overlaps `listen` (the same address, or the same port with either address unspecified). `serve --listen` is checked too.
- A meter provider in `Telemetry::start` with the Prometheus reader always, and an OTLP periodic reader (cumulative, counted by `CountingMetricExporter`) when OTLP is on. It is set as the global provider before `App::load`.
- `App::load_with_metrics` and `App::metrics()`; `mcp::testing::app_with_metrics` and `render` for later tasks' tests.
- Dependencies `opentelemetry-prometheus` 0.33.1 and `prometheus` 0.14.0 (no protobuf).

## Changed

- `ShutdownReport` gains `metrics`; the meter provider shuts down in the same parallel set and deadline as the other two.
- `serve` binds the `/metrics` listener before serving (a bind failure stops start-up), and after the HTTP server ends it stops the listener and waits for it before telemetry flushes.
- `mcp::annotations` is compiled outside tests, with `READS`, `STAGED` and `DESTRUCTIVE` `pub(crate)`.
- The plan has a dated correction note under Task 2.

## Notes

- `OTEL_SDK_DISABLED=true` turns OTLP off but leaves `/metrics` working.
- The OTLP metric reader's final export happens at shutdown; with a dead receiver it is bounded by the shutdown deadline like the other providers.
- Families recorded on events (requests, tools, publish) are added by Tasks 3-6 and checked by their own tests.
