## Added
- A mobile reader at `/read/`: an installable, read-only web app (iPhone
  through Add to Home Screen, Android through Chrome's install prompt) with
  the catalog picker, folder tree, concepts with outline, "Show the whole
  concept" and backlinks, `log.md` and `AGENTS.md` as documents, search,
  recent changes and an account screen. It signs in with the console's
  session cookie and returns to the route it was opened at.
- Offline reading: a service worker scoped to `/read/` precaches the reader
  and keeps network-first copies of opened concepts and documents (up to 200
  cached copies, least recently viewed out first; a concept kept in both short
  and whole form counts twice) and of the catalog list, trees, recent
  changes and backlinks. Home lists what is available offline.
- `GET /read/shell.json` lists the files the worker precaches with the SHA-256
  of the bytes this build serves; the worker installs only when the listing's
  version is its own and every file hashes as listed. `/read/sw.js` carries,
  as its version, a hash of every precached file (the shared console files
  included).
- `X-OKF-Account` on every `/api/v1` answer a route gives: an opaque tag of
  the account, which the worker uses to keep copies to one account. Any
  successful answer for another account, cached or not (the session check
  included), deletes the old account's copies and takes over (issue #858).
- `docs/reference/reader.md`, with links from the README and
  `docs/operations.md`.
- `just test-worker` and `tests/read_worker/` (Node's built-in runner, no npm
  packages), and browser journeys in `tests/ui_e2e/read.rs`.

## Changed
- `build.rs` embeds `src/http/read` as `READ_ASSETS` beside the console's
  `ASSETS`, through one shared function; the asset handler serves `png` and
  `webmanifest` types.
- Sign-in's `return_to` accepts same-origin `/read/` paths.
- `just test` runs `test-worker` first.

## Notes
- Cached copies are deleted on sign-out (twice: before the request, and again
  once the server confirms it), on any `401`, and by "Delete offline copies".
  A lost catalog grant evicts that catalog only; a deleted document evicts
  its own copies; `UnlockRequired` and `Suspended` keep them. The remembered
  catalog is forgotten on sign-out and on a `401`.
- Reads are network-first, so a revoked session never sees cached content
  while online.
- Known limits: iOS may evict an installed app's storage; an installed iOS app
  has its own cookie jar; a worker already retired cannot be reached by a
  mark; and Cache Storage refusing every delete leaves the old account's
  copies on disk, and a worker restart then serves them offline until a
  takeover succeeds and deletes them. Each is described
  in the reference.
