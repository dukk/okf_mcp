# M16 Task 9: OIDC flows in shared state (issue #562)

With `[redis]`, an OIDC sign-in or link flow started on one replica can
finish on another, and finishes once across all of them (spec Decisions 3-8,
16 and 20). Without `[redis]` the flows stay in this process's memory, as
before.

## Added

- `crate::oidc::session_hash`: the unpadded URL-safe base64 SHA-256 of a
  console session id, the only form a link flow stores it in.
- Tests in `src/http/oidc.rs`. Each Redis test runs twice, on a standalone
  Redis and on a one-node Valkey cluster:
  - a sign-in started on A finishes on B, and replaying it on A is refused;
  - a link flow replaces its session's previous one across replicas, leaving
    one `oidc:link` key and one `oidc:flow` key;
  - no Redis key or value holds the raw console session id or flow cookie;
  - a link flow finishes only in the session that started it (also run in
    memory): with another session's cookie the link is refused and nothing
    is linked; with its own cookie it links and keeps that session;
  - a Redis outage fails closed: the callback is a 503 "try again" page that
    keeps the flow cookie, and the start is a 503 with no flow cookie;
  - a flow whose take Redis refused (`ACL ... -@all`) finishes on reload
    once Redis answers again.
- Test support: `mcp::testing::replica_pair_on` (`replica_pair` over a Redis
  the test started) and `Browser::send_to` (send to one replica).

## Changed

- `OidcProviders::flows` is an `Ephemeral<Flow>` (`Keyspace::OidcFlow`) and
  `link_flows` is an `Index` (`IndexSpace::OidcLink`).
  `OidcProviders::new` takes `redis: Option<&Redis>`.
- `Flow`, `FlowSecrets` and `LinkRequest` derive serde. Their `Debug` stays
  hand-written and redacting.
- `LinkRequest.session_id` (the raw id) is now `session_hash`. The callback
  checks in constant time that the finishing request's own session cookie
  hashes to it, then gives that request's id to the store.
- `store_flow` is now `async` and returns `Result<bool, OkfError>`. It still
  removes the browser's previous flow and the session's previous link flow,
  and still refuses when memory is full.
- The callback's `take` is `GETDEL` in Redis. If Redis fails, the callback
  answers 503 `TRY_LATER` and never falls back to memory. That answer keeps
  the flow cookie, because the take may not have run (review of PR #576).
- `link_starts` stays per instance (#357).
