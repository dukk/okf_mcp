# M17 Task 11: the audit log shows people and targets by label

## Added
- `ActorView::Known.person_label` and `TargetView.person_label`: `user_label(audit_people.display_name, None)`, read from the audit snapshot. The snapshot has no email, so there is no email fallback; a deleted user's snapshot is blank (`forget_person`), so it reads `Unnamed user`, never the slug. `None` when there is no person.
- `TargetView.target_label`: for a `catalog` target the catalog's label, for a shared `team` target the team's label, both from `Labels` as the directory is now; `null` for a deleted catalog or team, a personal team, a hidden (operator) target and every other kind.
- `LIST_SQL` also reads `ap.display_name`, `tp.display_name` and `tt.name` (the shared team's slug).
- Tests: the listing's `person_label` from the snapshot and the placeholder after the user is deleted; `target_label` for a catalog and a shared team while they exist and `null` after the catalog is deleted; the slug filters still match; the export carries the labels; the audit page's person column shows the label and a label holding markup is drawn as text.

## Changed
- `audit::list` and `audit::export_lines` take a `&Labels`. The HTTP routes pass the key cache's directory; `okf-mcp audit list` and `export` load one (`Labels::load`). Every existing field keeps its shape; the new fields are additive, so the export gains them in its JSON objects.
- `audit.js`: the actor shows `person_label ?? person ?? label`, a user target its `person_label ?? person` (still linked by the slug), other targets `target_label ?? name`, with the slug as the tooltip of a labelled target. The filters keep matching slugs. Labels are drawn through `h()`, as text.
- `tests/ui_e2e/audit.rs`: the two journeys that matched a user's slug in the table create the user with a display name and match the label.

## Notes
- An actor that is a key or OAuth client passes through unchanged (epic decision 5); the audit actor is a credential, so nothing here maps an actor string to a user.
- The plan said the view gains `person_label` and `target_label`; they are on the nested `actor` and `target` objects, next to the `person` and `name` they label.
