# Issue #481: two tests that failed under load

## Fixed
- `okf::caller::tests::snapshot_build_documents_are_children_of_the_build_span` recorded no spans when the machine was busy. Cause, confirmed in `tracing-core` 0.1.36 and reproduced: while exactly one subscriber is alive, a thread reaching a callsite for the first time computes the callsite's cached interest from its own default subscriber only. A test thread with no subscriber that built a snapshot at that moment cached `read_document` as "never", although the other test's scoped subscriber was already registered, and nothing recomputed it. With two or more live subscribers the answer is computed from all of them.
- New `src/test_tracing.rs` (test builds only): `set_default`, `with_default` and `keep_alive` first create one inert subscriber that lives until the process exits, then install the test's subscriber, so the registry never holds a single subscriber and the race cannot occur. This removes the race instead of narrowing it; calling `rebuild_interest_cache` after installing would only have narrowed it, because a callsite first reached afterwards is not covered.
- The same helper now installs the subscriber of every test that counts or records events from callsites other tests also reach: the four in `src/okf/caller.rs`, `rows_returned::counting` (the size tests), the whoami statement-counting test in `src/http/api/identity.rs`, `Observer::start` (`src/telemetry/subscriber.rs`, 24 call sites across the telemetry tests, which no longer needs its own `rebuild_interest_cache`), the session-revocation log test in `src/http/mod.rs` and the two Redis-warning tests in `src/cli.rs`.
- New regression test `a_callsite_first_reached_by_a_thread_without_a_subscriber_is_still_recorded` reproduces the interleaving deterministically (another thread builds first while the test's subscriber is the only live one). It fails with `left: 0, right: 1` when the anchor is removed from `keep_alive`.
- `a_timed_out_tls_start_leaves_no_container` (`tests/tls.rs`) now accepts what a zero-length startup budget can end in at any stage: `StartupTimeout`, an I/O `TimedOut`, or a client or wrapped error that names a timeout. Anything else still fails, and the failure prints the error (`{error:?}`). The assertion that no container is left behind is unchanged. `only_timeout_class_errors_pass_the_zero_timeout_check` pins what the predicate accepts and refuses.

## Not changed
- Telemetry tests under `src/telemetry/` use `with_default` with callsites declared inside the test (`target: "okf_mcp::test"`), which no other test reaches, so they have no shared callsite to race on.
