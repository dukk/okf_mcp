# M19 Task 9: home and search (2026-11-20T22:23:34Z)

Issue #816, Task 9 of `docs/superpowers/plans/2026-11-20-mobile-reader-pwa.md`; also fixes
#843.

## Added

- `src/http/read/js/screens/home.js`: the search box, an iOS install hint (shown only in an
  iPhone or iPad browser that is not installed and has not dismissed it), recent changes in
  the current catalog, and an "Available offline" list. The list is drawn when the server
  cannot be reached (with "Nothing yet" if nothing was viewed) and below the cached recent
  changes when the worker answered from its cache.
- `src/http/read/js/screens/search.js`: hits for the query in the current catalog, or, when
  offline, a notice that search needs a connection with a link to home's offline list.
- Journeys in `tests/ui_e2e/read.rs`: `home_lists_recent_changes_and_search_finds_a_concept`,
  `a_log_in_recent_changes_opens_as_a_document`, `home_and_search_without_a_connection`,
  `home_lists_cached_recent_changes_and_viewed_concepts_offline`,
  `the_install_hint_shows_on_an_iphone_browser_until_dismissed` (shown, dismissed, absent
  on other browsers and when installed) and `an_account_without_an_email_shows_no_null`.

## Fixed

- #843: `screens/me.js` passed a conditional child to the native `append`, so an account with
  no email showed "null". It now draws with `fill`. A grep of `src/http/read/js/` found no
  other native `append` or `replaceChildren` call with a conditional child.

## Decisions

- Both screens check `ctx.live()` after every await before drawing or touching the banner;
  refusals still reach the ctx handlers through the exception path in `main.js`.
- The home journeys do not click the catalog picker (a later task): they open
  `#/t/main`, which remembers the catalog, then open home. The plan carries a dated
  correction.
- The no-email check was confirmed by reverting `me.js`: the journey then fails with the
  stray "null".
