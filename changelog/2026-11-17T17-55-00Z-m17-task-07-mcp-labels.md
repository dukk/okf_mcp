# M17 Task 7: labels beside ids in tool outputs

## Added
- `list_catalogs`: each catalog gains `display_name` (stored, empty when unset) and `label`; `suspended` gains `team_label`.
- `catalog_label` beside `catalog` on `get_concept`, `read_document`, `history`, `open_changeset`, `publish`, `discard`, `pending_changes`, `list_changesets`, search hits (`LabeledHit` wraps `CatalogHit`) and skipped catalogs, the five report tools (`open_questions`, `oldest`, `sprawl`, `links_report`, `lint`).
- `actor_label` on history revisions and listed changesets: the user's label when the actor is a user slug, else `null`. Key and OAuth actors pass through unchanged.
- `ToolContext::labels()` and `ToolContext::catalog_label(slug)` (the id when the directory does not know it yet).
- An `INSTRUCTIONS` paragraph: say the label, pass the id, never ask a person to type an id.

## Changed
- Every `catalog` parameter description says "catalog id (the `name` from `list_catalogs`)".
- `OkfError::Suspended` carries `catalog_label` and `team_label`; its text is `catalog "<label>" (<id>) is unavailable: its team "<label>" (<id>) is suspended`. The JSON error body keeps `catalog`, `team` and `notice`. Unknown-catalog errors are unchanged.
- `docs/reference/tools.md` regenerated.

## Tests
- `src/mcp/labels_tests.rs`: list labels, the suspended team label, history `actor_label` (user slug and `claude-code/x`), `catalog_label` on concept, document, search, changeset outputs, a changeset actor label, the suspended error text, the unknown-catalog error unchanged.
- `src/investigator/contract_tools.json` is re-captured (`cargo test --lib investigator_contract_capture_fixture -- --ignored`): the `search`, `get_concept` and `history` output schemas gained the new fields (`search` now names its hit definition `LabeledHit`). The `maintenance_*` outputs are unchanged on purpose: the runner parses them with `deny_unknown_fields`.

## Compatibility

Additive for MCP clients: the JSON gains keys and no existing key changes shape. The maintenance runner compares the server's `search`, `get_concept` and `history` output schemas with its pinned contract and fails closed on any structural difference, so deploy the runner image and the server from the same release. `list_catalogs`' `suspended` object and `OkfError::Suspended`'s message text also change (an extra `team_label`; the message names label and id).
