# M14 Task 8a: reading the audit log over REST (issue #402)

## Added

- `GET /api/v1/audit`: audit entries newest first, cursor-paged
  (`next_after`, `?after=`), with the filters `team`, `action`, `actor`,
  `target`, `since`, `until`, `after` and `limit` (1 to 500, default 100),
  plus every action name for the console's filter.
- `GET /api/v1/audit/export`: every entry the same filters select, as JSON
  Lines (`application/x-ndjson`, `audit.jsonl`).
- Who reads what: an every-catalog admin everything; a team's owner, only
  through a console session naming the team, that team's entries, scoped by
  the team's immutable audit id; a provisioner only its own entries (and no
  export: the provisioner gate allows `GET /api/v1/audit` only); anyone
  else 403.
- `store::audit::list` with `Viewer`, `AuditQuery`, `AuditRecord`,
  `ActorView` and `TargetView`; `store::audit::parse_filters` and
  `FilterText`, the one parser of the filters, for these routes and the CLI
  (Task 8b).
- `teams::owned_by` and `teams::owned_names`; `GET /api/v1/me` answers
  `owned_teams`.
- The "Audit API" section of `docs/operations.md`.

## Changed

- `GET /api/v1/me` runs its three reads concurrently.
- `docs/operations.md`'s API reference counts 90 endpoints (Audit, 2).

## Notes

- Owners' view, redacted on read (the stored entry never changes): an
  operator actor (admin credential or provisioner) is `{"kind":
  "operator"}` with no IP; IPs show only for the team's own members; a
  target person who was an admin user, and their key, grant or code, are
  hidden; `catalog.unlocked`'s `reason` is dropped (`OWNER_REDACTED`);
  `teams` lists only the owner's own team (new: an entry may also belong to
  another customer's team or a staff member's personal team, which reads as
  a person's name). Owners' actor and target filters never match an
  operator.
- A filter that can name nothing (a malformed team, a NUL in actor or
  target) matches nothing without reaching SQL, never a 500.
- `teams::owned_by` reads the `audit_teams` row rather than calling
  `audit_team_ref`, so reading the log never writes.
- Plan corrected (Task 8a's dated note, Task 8b's parse, the interfaces
  block) and the spec's "Who reads it" bullet added.
