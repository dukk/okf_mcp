## Added
- `GET /api/v1/oauth/codes` answers with `max_expiry_secs` (`oauth.code_max_expiry`), an additive field.
- The console's sign-in code form opens only once the limit is known (New reads the list itself when the first read is pending or failed; a failure is toasted and the form stays closed), and offers only the expiries within that limit. When none of 1h, 24h, 3d and 7d fits, the limit itself is the one choice. The default is 24h when allowed, else the longest choice.
- A redeemed code's drawer shows its grant id as a button that opens the grant's drawer (when the key list holds it; a grant outside the caller's reach stays text).
- Browser journeys for all of the above, and for the console's accent colour in both themes.

- The key rows and loader the code drawer uses to open a grant are scoped to each render, and a keys read that was overtaken or answers after the page was left draws nothing.

## Changed
- The token response no longer sets `Cache-Control: no-store` itself; the `/oauth/*` route layer sets it, and a test checks it appears exactly once. `Pragma: no-cache` stays on the response.
- The consent Approve handler reloads only the key cache (`App::reload_keys_now(true)`, announcing to other replicas) instead of a full `poll()` over every catalog.
- `styles.css` maps its colours onto Pico's variables with a selector that outranks Pico's `:root:not([data-theme=dark])`, so the light theme's form colours are the console's own.
